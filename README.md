# ComicManager

**漫画库的两件事：把 EPUB 整理成 Kavita / Komga 认得出的 CBZ，再把已有 CBZ 的元数据补齐。**

格式转换按 OPF 的 `spine` 取真实页序、重算卷号、写全 ComicInfo，图片字节原样搬运 —— 不重编码、不降低画质。
元数据刮削从 Bangumi / MangaUpdates / MangaDex 取资料，也可以纯手填，一次写进包内 `ComicInfo.xml`。

## 30 秒上手

安装后运行程序，顶部三个页签随时切换，两个功能共用同一份源目录设置：

**格式转换**

1. 左栏 **源目录** 点「+ 添加目录」，选中放 EPUB 的文件夹（可加多个，会递归查找）
2. 左栏 **输出目录** 选 CBZ 要生成到哪
3. 中栏选 **目标服务器**（不确定就留「双兼容」）和 **阅读方向**（留「自动判断」）
4. 点 **预演** 看一眼命名对不对 → 点 **开始**

**元数据刮削**

1. 左栏 **扫描范围** 添加漫画库根目录（递归扫 `.cbz`，一个文件夹算一个系列）
2. 勾选元数据来源（默认 Bangumi + MangaUpdates）
3. 中栏选中一个系列 → **搜索** → 从结果里挑一条
4. 右栏核对字段（「对比」页签能看将要覆盖什么）→ **写入整组**

## 它解决什么

### 转换：站点导出的 EPUB 有四个坑

| 问题 | 直接用会怎样 | 本程序 |
|---|---|---|
| 图片文件名是随机 ID（`vol-005318.jpg`），与页码无关 | 按文件名排序得到乱序漫画，翻两页不一定发现 | 读 OPF 的 `spine`，按真实页序重排 |
| 新旧两代生成器结构不同：早期 calibre 转的缺 `fixed-layout`，后期自研的每页套一层 HTML | KOReader 打开前者白屏；后者正文层干扰取图 | 直接抽 `spine` 指向的图片，无视包装层 |
| `calibre:series_index` 全是 `1.0` | 不管多少卷全排成第 1 卷，互相覆盖 | 从文件名与 OPF 重算卷号；无卷号的按自然序续编 |
| 没有 ComicInfo，或字段残缺 | 服务器刮削后排序、阅读方向全错 | 写全 `Series` / `Volume` / `Number` / `Manga` 等字段 |

### 刮削：中文漫画库的元数据基本是空的

| 问题 | 本程序 |
|---|---|
| 中文漫画在 ComicVine / AniList 上命中率极低 | 换 Bangumi / MangaUpdates / MangaDex，按中文名与别名匹配 |
| 一个来源的字段总缺几项（Bangumi 没分级、MangaDex 没出版社） | 勾几个来源就互补，缺字段自动补齐，已有值不动 |
| 手动改 XML 容易写坏包 | 只替换包内 `ComicInfo.xml`，图片不动，可自动备份 `.bak` |
| 刮错了想退回原样 | 覆盖前的 XML 自动留档在文件末尾，一键「元数据回退」 |

## 功能

| 能力 | 说明 |
|---|---|
| **EPUB → CBZ** | 按 `spine` 取页序；图片字节原样拷贝，**不重编码、不降低画质** |
| **格式互转** | 已有 CBZ 在 Kavita / Komga 两种命名与元数据规则间互换，图片不动 |
| **元数据刮削** | Bangumi / MangaUpdates / MangaDex 三源，按系列匹配；结果可手改，也能纯手填 |
| **跨源补齐** | 一个来源缺的字段用其它已勾选来源补，只补空值，不覆盖已有内容 |
| **封面** | 从来源下载系列封面（中文版 / 原版可选，可限宽），写成系列目录的 `cover.jpg` |
| **series.json** | 必写的系列级元数据文件：Kavita Custom 档写侧车格式（简介 / 状态 / 年份 / 类型 / 标签 / 人员 / 链接等 12 类字段），其余档位写 Mylar 格式 |
| **写回方式** | 只换包内 `ComicInfo.xml`；可选 `.bak` 备份，覆盖前的 XML 总是留档成注释 |
| **元数据回退** | 从留档里读回写入前的字段，填回表单，随时能退回 |
| **模板重命名** | 按 `{series}/{id}` 之类的模板归档，先预览再执行 |
| **双服务器格式** | Kavita 按 `Volume`（`系列 v01.cbz`）/ Komga 按 `Number`（`系列 #001.cbz`）/ 双兼容 |
| **阅读方向自动判断** | 结合始发国线索和页面比例判断，必要时联网查证；结果写入 ComicInfo |
| **繁转简** | 内置 OpenCC 词表（台湾正体 / 通用繁体 → 简体），含假名的日文标题整条保留 |
| **番外处理** | 转换时独立成系列或作小数号；刮削时用 `Format=Special` 标记，编号 SP01 起，号位可选「不写 Number」「番外卷号占 0」 |
| **并行与续跑** | 转换默认 6 并发（1–32）；刮削按系列并发（1–8），目标已存在即跳过 |
| **配置持久化** | 设置存 `config.json`，转换页与刮削页各存各的，下次打开自动恢复 |

## 格式转换选项

| 选项 | 默认值 | 说明 |
|---|---|---|
| 任务类型 | EPUB → CBZ | 「格式互转」处理已有 CBZ；该模式下没有「预演」按钮 |
| 源目录 | 空 | 可加多个，递归查找。转换模式找 `.epub`，互转模式找 `.cbz` |
| 输出目录 | 空 | 按系列自动建子目录，不会把上百个文件堆在一层 |
| 目标服务器 | 双兼容 | `Volume` 与 `Number` 都写，两边都能正确排序；切换时自动改文件名模板 |
| 文件名模板 | `{series} v{vol:02d}` | Komga 用 `{series} #{vol3}`；变量见[命名规则](#命名规则) |
| 阅读方向 | 自动判断 | 也可固定右开 / 左开 / 上到下；固定时不联网 |
| 繁转简 | 台湾正体 | 可选「不转」「台湾正体（`tw2s`）」「通用繁体（`t2s`）」 |
| 卷名 / 话名也繁转简 | 开 | 括号里的原卷标签跟着一起转；关掉则保留原始字形（`馮寶寶03`、`話532-554`） |
| 番外 / 特别篇 | 独立成系列 | 「接在正传后」会把番外 03 写成 `Number = 2.5` 这种小数号 |
| 压缩方式 | 不压缩 | 漫画图片本身已是压缩格式，`Deflate` 只省一点体积却明显更慢 |
| 并发数 | 6 | 1–32；机械硬盘上 4 左右更稳，SSD 上 8–12 更快 |
| 保留原卷标签 | 开 | 保留原始卷名，写成 `一人之下 v37 (话532-554).cbz` |
| 剔除站点水印页 | 开 | 按文件名剔掉 `createby.*`、`logo.png` 这类站点插入页 |
| 覆盖已存在文件 | 关 | 关闭时目标存在即计为「跳过」；开启后重做并覆盖 |
| 只处理前 N 个 | 关 | 大批量试跑用，确认效果再放开 |

**停止**：点停止后不再开始新文件，正在转换的那几个收尾后退出，已生成的 CBZ 都是完整的。

## 元数据刮削

### 三个来源怎么分工

| 来源 | 强项 | 备注 |
|---|---|---|
| Bangumi | 中文书名、出版社、卷数、书系最全 | 中文漫画库首选；不提供语言与年龄分级 |
| MangaUpdates | 英文与日文条目最全，作者、年份、类型稳 | 成人向分级（Adult / Mature）在此 |
| MangaDex | 封面质量最好，简介多语言，别名最杂 | 默认不勾，需要封面或简介时再打开 |

搜索结果按匹配度排序（同分保持来源顺序）。匹配用「去标点整串比较 + 二元组重合度」，并比对候选的全部别名 —— 拿中文名搜 MangaDex 时，主标题是英文，全靠别名命中。

### 抓取与写入

| 选项 | 默认值 | 说明 |
|---|---|---|
| 缺字段时用其他来源补齐 | 开 | 只补空字段，来源已经给了值的不动 |
| 批量取首条（只填不写） | — | 给每个系列自动挑匹配度最高的候选填进表单，不落盘 |
| 写入目标 | Kavita Custom | 三档：Kavita Custom / Kavita / Komga。Kavita 系按 `Volume` 归卷、Komga 按 `Number` 排序，切换时写号预设跟着变 |
| 不写 Number | 开 | Kavita 系档位：正传只写 `Volume`，话只写话（`Number`），两个字段不互相抄；单册里手动改过的册以手动值为准。Komga 档不生效 |
| 番外卷号占 0 | 开（Kavita Custom 档） | 番外的 `Volume` 写 `0` 而不是清空，`Number` 按原顺序保留（Specials 区排序用）；关掉则番外卷号清空。Komga 档不生效 |
| 备份 `.bak` | 关 | 打开后写入前把原包另存一份同目录 `.bak`（只保留第一份，后面的写入不覆盖它） |
| series.json | 必写 | 写到系列目录根部：Kavita Custom 档写侧车格式（排序名 / 译名 / 简介 / 状态 / 年份 / 语言 / 分级 / 出版社 / 类型 / 标签 / 人员 / 链接），其余档位写 Mylar 格式 |
| 生成收藏 | 开 | 写 `SeriesGroup`，Kavita 只认这个字段自动建「收藏」；关掉就不写 |
| 下载封面 | 开 | 写到系列目录的 `cover.jpg` |
| 覆盖封面 | 关 | 已有 `cover.jpg` 时是否替换 |
| 封面版本 | 自动（中文优先） | 可选中文版 / 原始版；MangaDex 的封面按语言分开 |
| 封面尺寸 | ≤800 宽 | 可选原图 / ≤1200 宽 |
| 并发 | 3 | 同时写入的系列数，1–8 |

### 元数据表单

字段按「系列 / 分册与号 / 阅读与分类」分组：

- **系列**：系列名（译名优先）、原名（保留在 `LocalizedSeries`）、排序名、总卷数、合集 / 书单、品牌 / 书系、出版社
- **分册与号**：一本一本单独改号（`Volume` / `Number` / 单册标题 / 特殊类型 / 年份 / 语言）；分册停在「整组」时改的是整组共用的字段
- **阅读与分类**：阅读方向、年龄分级、ISBN、作者、画师、译者、类型、标签、网络链接、备注、简介

「对比」页签列出「现有（文件内）」与「新值」的差异，只写有变化的字段。「清除预览」清空下面的 XML 预览，「元数据回退」把留档里的旧值填回表单（只改表单，不写盘）。

> `语言（这一本）` 说的是你收藏的这一版是什么语言，不是原作语言。中文版就选中文 —— 选错会让 Komga 的语言筛选整片乱掉。

### 按模板重命名

默认模板 `{series}/{id}`，相对库根目录、不含扩展名，`{series}` 里带 `/` 会当成目录层级。

| 变量 | 含义 |
|---|---|
| `{series}` | 系列名 |
| `{id}` | 册号标签：正传 `V01`，番外 `SP01` |
| `{volume}` / `{number}` | 卷号 / 话号原值 |
| `{title}` | 单册标题 |
| `{year}` | 年份 |

先点「预览」看结果，再点「执行」；预览和执行走同一套渲染，看到的名字就是真改成的名字。

### 扫描规则

- 递归扫源目录下的 `.cbz`，**一个父文件夹算一个系列**（Komga / Kavita 就是这么认的）
- 只收 `.cbz`：CBR 是 RAR，改不了包内文件，列出来只会让人误点
- 号优先取包内 ComicInfo，没有再解析文件名；文件名里没号的按排序补号，不会全写成同一个号
- 番外按出现顺序编 `SP01`、`SP02`，正传按卷号编 `V01`、`V02`

## 安装

运行安装包 `ComicManager-<版本>-setup.exe`：

1. **欢迎** → **选择安装模式**
   - **仅为我安装**（默认）：`%LOCALAPPDATA%\Programs\ComicManager`，不需要管理员权限
   - **为所有用户安装**：`%ProgramFiles%\ComicManager`，会请求一次 UAC 提权
2. **许可协议**（MIT）→ **选择安装位置**（可浏览换目录，选完自动补上 `\ComicManager` 一层）
   - 这个位置装过的话，页面上会写明已装的是哪一版、这次是更新 / 重装 / 降级，以及检测到的 `config.json` 路径
   - 路径写错或目标盘空间不足，直接在页内提示并把「下一步」置灰，不弹框
3. **附加任务**：桌面快捷方式 / 开始菜单快捷方式 / 安装完成后立即运行
   - **装过 1.x（ComicConverter）时会多出一块「检测到旧版」**：勾选「卸载旧版并沿用设置与阅读方向缓存」，装完自动收掉旧程序、旧快捷方式和旧卸载登记，并把 `config.json` 与阅读方向缓存带过来；取消勾选则新旧并存
4. **准备安装** → 安装 → **完成**

装完在「设置 → 应用 → 已安装的应用」里正常卸载。点「卸载」时才检查程序是否在运行，命中就切到「正在运行」页：可点「结束进程并继续卸载」，也可「上一步」返回确认页。

卸载会移除程序文件、快捷方式、注册表登记与 WebView2 缓存；**`config.json` 默认保留**（可取消勾选一并删除），重装后设置还在。若有文件因为被占用没删掉，会进「卸载未完全成功」页并给出安装目录路径，可「重试」或关闭后手动删除。

### 从 1.x 升级

1.0.x 的程序叫 ComicConverter，卸载项、安装目录、缓存目录都是另一个名字。2.0 的安装器会自动识别：

- 在「附加任务」页显示旧版版本与位置
- 勾选后：复制旧 `config.json`（新目录还没有配置时）→ 复制阅读方向缓存 → 删旧快捷方式与卸载登记 → 删旧安装目录与旧缓存目录
- 旧版正在运行、或设置文件复制失败时**不删旧目录**，完成页会用警示色写清哪一步没做成，可手动清理
- 用 `--silent` 静默安装时不动旧版

### 文件都在哪

| 文件 | 位置 | 用途 |
|---|---|---|
| `config.json` | exe 同目录 | 全部界面设置（转换页与刮削页各存各的）；删掉等于恢复默认 |
| `error.log` | exe 同目录 | 未处理异常的堆栈；正常运行时不会生成 |
| `origin-cache.json` | `%LOCALAPPDATA%\ComicManager\` | 阅读方向判定缓存，跟着用户走而不是跟着安装目录走 |
| `README.md` | exe 同目录 | 安装包内嵌的使用说明，装完可直接打开 |

刮削还会在你的漫画库里留下这些文件：

| 文件 | 位置 | 用途 |
|---|---|---|
| `ComicInfo.xml` | CBZ 包内 | 元数据本体，只替换这一个条目 |
| `*.cbz.bak` | 与原包同目录 | 写入前的整包备份（关掉「备份 .bak」就不生成） |
| `series.json` | 系列目录根部 | 系列级元数据：Kavita Custom 库按它读系列数据（优先级高于 ComicInfo）；Komga 写 Mylar 格式 |
| `cover.jpg` | 系列目录根部 | 系列封面 |

- Windows 10 / 11（x64）
- .NET Framework 4.8（未安装时需先安装）
- WebView2 Runtime（Win11 自带；Win10 未装时程序内会提示，也可从「工具 → 获取 WebView2 运行时」打开下载页）

## 命名规则

默认模板 `{series} v{vol:02d}`（Kavita / 双兼容）、`{series} #{vol3}`（Komga）。

| 原始文件名 | Kavita / 双兼容 | Komga |
|---|---|---|
| `Y之樂園 - 卷01 - 高橋直樹.epub` | `Y之乐园 v01.cbz` | `Y之乐园 #001.cbz` |
| `一人之下 - 03馮寶寶03 - 米二.epub` | `一人之下 v03 (冯宝宝03).cbz` | `一人之下 #003 (冯宝宝03).cbz` |
| `一人之下 - 話532-554 - 米二.epub` | `一人之下 v37 (话532-554).cbz` | `一人之下 #037 (话532-554).cbz` |
| `[Kox][○成]卷01.kepub.epub` | `○成 v01.cbz` | `○成 #001.cbz` |
| `WhatDoesTheFoxSay - 番外03.epub` | `WhatDoesTheFoxSay 番外/… 番外 v03.cbz` | `WhatDoesTheFoxSay 番外/… 番外 #003.cbz` |

几条约定：

- **原卷标签进括号**：Kavita 与 Komga 的解析器都把 `()` 当作附加信息，不会误读成卷号。例表里是开了繁转简的结果，关掉「卷名 / 话名也繁转简」就保留 `(馮寶寶03)`。
- **模板变量**：`{series}` 系列名、`{vol}` 卷号、`{vol:02d}` 两位补零、`{vol3}` 三位补零。
- **无卷号的卷**（`正傳Part1`、`連載前短篇`）按文件名自然序续编，不会全挤成 `v01` 互相覆盖。
- **卷号识别**：`第 N 卷 / 話 / 集`、`卷N`、`vN` / `vol.N`、`#N`、开头纯数字，依次尝试。
- **清洗**：`\ / : * ? " < > |` 换成 `_`；全角 `：？＊／＼＜＞｜＂` 同样处理；全角空格转半角；系列名截到 120 字、文件名 110 字、卷标签 40 字。
- **番外独立成系列**时目录名为 `{系列} 番外`，与正传分开，避免卷序互相污染。

## ComicInfo 字段

转换与刮削写的是同一套字段，只是来源不同（文件名 / OPF / 刮削结果 / 手填）。

| 字段 | 来源 | 用途 |
|---|---|---|
| `Series` / `SeriesSort` / `LocalizedSeries` | 系列名 / 排序名 / 原名 | 归并系列；Kavita 用 `LocalizedSeries` 合并中日英混排的同一系列 |
| `Volume` / `Number` | 解析或手填 | **Kavita 按 `Volume`、Komga 按 `Number` 排序** |
| `Count` | 总卷（话）数 | 系列完整度 |
| `Title` | 单册标题 | 显示 |
| `Summary` | 简介（去掉 HTML） | 详情页 |
| `Year` / `Month` / `Day` | 出版时间 | 时间线 |
| `Writer` / `Penciller` / `Translator` / `Publisher` / `Imprint` | 作者、画师、译者、出版社、书系 | 分类与检索 |
| `Genre` / `Tags` | 类型 / 标签 | Komga 走 Genre，Kavita 筛选看 Tags |
| `SeriesGroup` | 合集 / 书单 | 跨系列归档 |
| `Format` | 特殊类型 | `Special`（番外）/ `TPB` / `Annual` / `One-Shot` / `Omnibus` |
| `GTIN` | ISBN（纯数字） | 每本一个 |
| `PageCount` / `LanguageISO` | 实际页数 / 这一本的语言 | 阅读器行为与筛选 |
| `Manga` | 阅读方向 | 右开写 `YesAndRightToLeft`，其余写 `No`，不确定则不写 |
| `AgeRating` | 年龄分级 | `Everyone` / `Teen` / `Teen+` / `Mature` / `Adults Only` |
| `Web` / `Notes` | 链接 / 备注 | 溯源信息 |
| `OriginCountry` / `ReadingMode` | 自动判断结果 | 换目录重跑时复用判定，减少联网 |

`Volume` 和 `Number` 在「双兼容」档下**必须都写**：只写一个，另一边就会乱序。

> `OriginCountry` 与 `ReadingMode` 不是 ComicInfo 标准字段。Kavita（`XmlSerializer`）与 Komga（Jackson `@JsonIgnoreProperties(ignoreUnknown = true)`）都会忽略未知元素，不影响刮削；写进去是为了换目录重跑时复用判定结果，减少联网查询。

## 阅读方向怎么判断

程序先推断始发国，按以下线索依次尝试：

1. 元数据中的始发国。
2. `origin-cache.json` 中的历史结果。
3. `dc:language`、出版社、标题文字。
4. 自动模式下前述线索不足时，查询 Wikidata：会发送系列名，必要时也发送作者名；参考国家/地区和语言等信息，并对非漫画类结果降低评分。

随后决定阅读方向：手动选择优先；自动模式下抽样页面的高宽比中位数达到 2.0 时判为上到下，否则按始发国决定；仍无法判断时默认右开。页面比例为长条也可能先进行始发国联网查询。

刮削侧另有更直接的线索：MangaUpdates 的 `Type`（Manga 右开 / Manhwa、Manhua 左开）与 MangaDex 的 `originalLanguage`，只在语言已知时推方向，推不出来就留空让服务器自判。

结果写入 `ComicInfo.xml`。联网成功或查询结果被判定为未找到时会尝试缓存；缓存写入可能失败，不能保证下次一定不联网。

联网请求设置 6 秒超时；每次扫描最多进行 150 次系列查询（一次查询可能包含多个 HTTP 请求），首次查询后有 120 秒的发起查询时间预算，连续失败达到阈值时停止后续查询。这些限制不是整个扫描的硬性总时长。

手动选右开 / 左开 / 上到下时不联网，仍会通过离线线索推断 `OriginCountry`。

## 常见问题

**2.0 和以前的 ComicConverter 是什么关系？**
同一个程序。2.0 改名 ComicManager 并加入元数据刮削，1.x 的转换功能与配置项都还在。安装包里带了旧版识别，见[从 1.x 升级](#从-1x-升级)。

**仓库地址变了吗？**
仓库和程序一起改名成了 ComicManager，旧地址 `ComicConverter` 由 GitHub 自动重定向，已有链接不会失效。Releases 与 issue 都在新地址。

**转完在 Kavita 里还是乱序？**
先确认输出时选的目标服务器和 Kavita 实际用的排序依据一致：Kavita 只认 `Volume`。如果当时选了 Komga，文件名是 `#001`，`Volume` 未必合预期。改回「双兼容」重跑一遍即可，图片不会被重编码。

**刮削会改动图片吗？**
不会。只替换包内 `ComicInfo.xml`；开了「备份 .bak」还会留一份原包。图片字节从不重写。

**刮错了怎么退回去？**
两种办法：把同目录的 `*.cbz.bak` 覆盖回原文件名；或者用「元数据回退」从留档注释里读回旧字段，再手改。

**一个系列搜不到怎么办？**
换关键词（中文名 / 日文原名 / 英文名都试一次），或换来源。都搜不到就在表单里手填 —— 字段不必全填，至少要 `系列名`。

**番外编号为什么是 SP01 而不是 V01？**
番外常和正传同卷号，两个 `V01` 在列表里分不清谁是谁。刮削侧统一用 `SP01` 起编，`Format` 标成 `Special`，Kavita 与 Komga 都认这个标记。

**会改动我原来的 EPUB 吗？**
不会。源目录只读，全程只往输出目录写 `*.cbz`。

**转换中途关了程序 / 断电了？**
直接重跑即可：已经转换完的记「跳过」，不会重复打包。注意断电那一刻正在写的那个文件可能是残缺的，而它已经存在、会被当作已完成 —— 保险做法是勾上「覆盖已存在文件」再跑一遍，或先删掉输出目录里可疑的那个 `.cbz`。

**提示 WebView2 缺失、界面白屏？**
Win11 自带；Win10 多数已随 Edge 安装。缺的时候程序会显示提示和下载入口，也可用「工具 → 获取 WebView2 运行时」。

**繁转简把标题转坏了？**
含假名的日文标题会整条保留，不参与转换。若简体系列名被误转，把「繁转简」设为「不转」再跑（已生成的要开「覆盖」重做）。只想保留括号里的原始话名，关掉「卷名 / 话名也繁转简」即可，系列名照旧转换。

**杀毒软件报可疑？**
exe 没有代码签名，这是误报最常见的原因。可以先本地比对文件哈希，或者直接从源码自行编译（见 `DEVELOPMENT.md`）。

**能命令行批量跑吗？**
只有图形界面。安装包支持 `--silent`：按当前安装模式装到默认目录、创建桌面与开始菜单快捷方式、装完不自动运行，也不处理 1.x 旧版。转换与刮削没有命令行参数；要脚本化可以预先写好 `config.json` 再启动程序。

## 已知限制

- 只处理**元数据与文件名**，图片里已经画上去的字无法转简体
- 转换页只写包里能读到的字段（文件名 / OPF）；要联网补全作者、简介、封面，用刮削页
- 自动判断可能判错（同名作品、简繁混写、冷门作品查不到），判错就在界面上手动指定方向；已写入 `OriginCountry` 的文件重跑不会被改
- 三个来源都是公开 API，条目以日韩与港台出版物为主；简体中文网络漫画的命中率仍有限
- 只收 `.cbz`：CBR（RAR）无法写入包内文件
- WebView2 Runtime 缺失时界面无法加载，只能看到下载提示
- 只支持 Windows，没有 Linux / macOS 版本计划
